# Project profile

Updated 2026-10-06. **Current scope: standards first and a marked implementation roadmap; only previously started bootstrap/domain work is completed.** Target architecture statements below are design contracts, not claims of implemented runtime behavior. See [roadmap](implementation-roadmap.md).

The target is one NestJS modular monolith, separate API/worker entry points and a static browser client. Identity owns users/roles/permissions/sessions. Catalog owns exams/sections/question bank/options/published snapshots. Assessment owns attempt/answers/result and leaderboard/statistic projections. Reporting owns read-only admin queries. Audit writes use a platform port in admin transactions. Refer to [module guide](examination-module-guide.md) and architecture §§77–79.

PostgreSQL is authoritative. Parameterized `pg` adapters implement business ports (ADR-001); no driver/client/SQL/SDK/Nest dependencies in Domain/Application. UnitOfWork and AsyncLocalStorage remain infrastructure, with join/rollback-only semantics. Versioned SQL migrations under `apps/api/migrations` are required but not implemented yet. TypeORM may be introduced through an ADR/measurement; synchronize is never permitted in production.

HTTP envelope: `{data,errorCode,message,status}`, following the supplied contract's safe same-text errorCode/message. Cursor pagination adds `{next,pageSize}` metadata by ADR-002. Health `/live` and `/ready` stay outside the envelope; correlation IDs use headers/log context. These endpoints are planned, not implemented.

The current domain helper models CREATED, IN_PROGRESS, SUBMITTED, PROCESSING, COMPLETED, EXPIRED and FAILED; expired submissions can be scored and retain `expired=true`. It accepts injected server time. Production must resolve authoritative time after obtaining the write lock. Exact-match grading uses positive integer points and no partial credit for the three requested question types; product-specific TOEIC/IELTS scale conversion is not implied. Persistence/races/receipts/ownership and worker retry/replay still need implementation and real integration tests.

Initial target workload: 2,000 simultaneous candidates; scheduled 100→500→2,000 start burst, 45-minute saves, synchronized submit, five-minute polling and leaderboard burst. SLO proposals: 99.9% monthly availability, GET exam p95 <250ms, answer save p95 <300ms, submit acknowledgement p95 <500ms, unexpected error rate <1%, 99% scoring within 60s at committed peak. GET questions/result/leaderboard p95/p99, autosave/poll intervals and payload assumptions must be specified before capacity acceptance. These are **unverified targets**. Proposed disaster RPO ≤5min / RTO ≤30min requires a timed restore; ordinary AZ failover needs separate evidence.

Target AWS services: CloudFront/WAF, ALB/private ECS, ECR, encrypted private Multi-AZ RDS, SQS/DLQ, private S3, Secrets Manager/SSM and CloudWatch. Route53/custom domain is optional; no domain exists. AWS account/profile/region remain unselected. Singapore is only an example region. Redis/Kafka/RDS Proxy stay absent unless justified. NAT vs interface endpoint topology, compute sizing/architecture, scaling targets and minimum worker capacity require a resource/cost ledger and benchmarks. A non-Spot API baseline across AZs is an availability requirement. Origin certificate/TLS design remains pending; no HTTPS requirement is waived.

Initial observability policy proposal: redacted structured logs; 14-day diagnostics; 5% traces; route/status labels only; no IDs in metric labels. Audit retention and cost/telemetry budget need final selection and measurement. Record changes in the owning standards and ledger, not only this profile.

Current environment: TypeScript/Jest domain bootstrap and local PostgreSQL/ElasticMQ Compose setup. No production credentials/resources, API/controller, SQL migrations, scoring worker, frontend, Terraform or load-test implementation has been delivered. The [production acceptance ledger](production-acceptance.md) tracks what remains unmeasured.
