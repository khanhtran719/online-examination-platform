# Project profile

Updated 2026-10-06. **Current stage: Phase04 Identity core and API/email-worker composition roots delivered locally; browser HTTPS and live SES operations remain pending.** Active increment is [source-layout normalization](architecture-normalization-plan.md) and [API review](api-architecture-review.md), documentation complete and runtime moves pending. DB-12 image drill remains open. Git now exists with an origin remote; BOOT-09 delivery branch/PR workflow is not yet validated. See [runtime review](phase-04-review.md), [roadmap](implementation-roadmap.md), [product specification](product-specification.md), [permissions](security-and-permissions.md), [HTTP/events](contracts/README.md) and [SLO/workload](slo-and-workload.md). Local evidence does not constitute production acceptance.

The target is one NestJS modular monolith, separate API/worker entry points and a static browser client. Identity owns users/roles/permissions/sessions. Catalog owns exams/sections/question bank/options/published snapshots. Assessment owns attempt/answers/result and leaderboard/statistic projections. Reporting owns read-only admin queries. Audit writes use a shared application port in admin transactions; the current legacy path is platform/application during ADR-006 transition. Refer to [module guide](examination-module-guide.md) and architecture §§77–79.

Identity [ADR-005](adr/005-email-verification-and-signed-tokens.md) is implemented for email/password, single-use30min verification and final email-owner password. Access/refresh use ES256/P-256; PostgreSQL controls live sessions/rotation/revocation/current permissions. Real restricted-PG tests cover concurrent refresh/activation, atomic rate admission, logout retries and audited operator actions. Cookies/CSRF are implemented at the HTTP boundary; actual browser HTTPS remains ID-07. Identity owns encrypted durable email intents, leases/fencing, retry/park/replay and bounded maintenance. SMTP delivery was captured locally; SES request/timeout adapter tests are not live SES delivery. Magic link/GitHub remain later ID-12/13. No extra email queue/Redis baseline.

Current source (before ADR-006 normalization) uses: `modules/identity/application/ports`, `domain/errors`, `infrastructure/{persistence,security,mail,http}` and `presentation/http/dto`; technical `platform/{application,domain,infrastructure,presentation}` cannot import a business module. Presentation depends on an inbound HTTP-session port, not its infrastructure implementation. Module-level Nest factories wire plain application classes. `AppModule` imports DatabaseModule, HealthModule and IdentityModule; API and worker are separate entry points. Framework runtime is Nest12/Fastify5 on Node24, with JOSE/Argon2/SMTP/SES confined to adapters.

Target placement is `apps/api/src/{config,shared,modules,infrastructure,workers}` under architecture §5/[ADR-006](adr/006-source-layout-normalization.md). Pure shared Domain/Application do not import Nest helpers in shared/common; global infrastructure does not own business adapters. The [normalization plan](architecture-normalization-plan.md) maps current paths, explicit transition and real-check gates; runtime is not yet conformed.

PostgreSQL is authoritative. Parameterized `pg` adapters implement business ports (ADR-001); no driver/client/SQL/SDK/Nest dependencies in Domain/Application. Plain UnitOfWork has implemented join/rollback-only semantics and real DB tests. Eight versioned SQL migrations under `apps/api/migrations` preserve the first six checksums. API, mail worker, operator and migration roles have separate grants; bounded pools/timeouts and local pg_stat_statements are implemented. Identity repository/receipts/auth projections are implemented; Catalog/Assessment/Reporting adapters remain subsequent work. See [database guide](database.md), [ADR-004](adr/004-postgresql-durability.md). The current pg implementation is not a measured winner over ORM. TypeORM + raw projections is the proposed evaluation candidate, Sequelize is also allowed; selection requires the O-01–04 comparison and a separate ADR. Synchronize remains forbidden. Target migration placement is `src/infrastructure/database/migrations`, preserving checksums/history and copying SQL assets into the build; current paths stay until N-09.

HTTP envelope: `{data,errorCode,message,status}`. Success leaves `errorCode` and `message` null. Errors use the same safe text for both fields. Global response/filter tests enforce this contract. Health `/live` and `/ready` run outside the envelope; server-issued correlation IDs use headers/structured logs. Nine Identity operations are implemented; the other OpenAPI operations remain specifications. Cursor pagination adds `{next,pageSize}` metadata by ADR-002 for future list endpoints.

The current domain helper models CREATED, IN_PROGRESS, SUBMITTED, PROCESSING, COMPLETED, EXPIRED and FAILED; expired submissions can be scored and retain `expired=true`. It accepts injected server time. Production must resolve authoritative time after obtaining the write lock. Adopted v1 uses EXACT_MATCH_V1, integer points/no partial credit, deadline=min(start+duration,frozen close), limits across versions, NEVER explanations by default, opt-in best-score leaderboard per version and transaction-local PROCESSING. [ADR-003](adr/003-idempotency-retention.md) defines UUIDv7 first-use freshness and seven-day durable receipts. Helper tests do not implement publication/session/retention/receipt policies; persistence/races/ownership and worker retry/replay still need real integration tests.

Specified target workload: 2,000 simultaneous candidates; 100→500→2,000 arrivals, 10s mass start/submit, 100-question baseline, 45min changed-answer batches every10s±20% jitter, bounded polling2→10s and leaderboard burst. [SLO/workload](slo-and-workload.md) defines all hot-route p95/p99/query budgets, request error-budget populations and dataset/traffic parameters. Targets: 99.9% monthly availability, GET exam p95<250ms, answer save<300ms, submit ACK<500ms, unexpected errors<1%, 99% scoring≤60s. These are **specified but unverified targets**. Disaster RPO≤5min/RTO≤30min, seven-day PITR baseline and ordinary failover≤120s require actual timed tests, not specification acceptance.

Target AWS services: CloudFront/WAF, ALB/private ECS, ECR, encrypted private Multi-AZ RDS, SQS/DLQ, private S3, Secrets Manager/SSM and CloudWatch. Route53/custom domain is optional; no domain exists. AWS account/profile/region remain unselected. Singapore is only an example region. Redis/Kafka/RDS Proxy stay absent unless justified. NAT vs interface endpoint topology, compute sizing/architecture, scaling targets and minimum worker capacity require a resource/cost ledger and benchmarks. A non-Spot API baseline across AZs is an availability requirement. Origin certificate/TLS design remains pending; no HTTPS requirement is waived.

Initial observability contract: redacted structured logs, 14-day diagnostics, 5% baseline traces, route/status labels only and no IDs in metric labels; audit365days and unsampled. Session/attempt/snapshot/outbox/inbox/import retention is specified in [permissions](security-and-permissions.md). Telemetry cost budget/sampling overhead remains unmeasured; record changes in owning contracts and ledger, not only this profile.

Current evidence:90 unit/tooling cases and52 real-PG/HTTP/mail integration cases pass; actual API/worker entry-point smoke and SIGTERM exit pass. Local diagnostic benchmark uses two API instances and retains raw samples, CPU/RSS/query/pool metrics in [experiment](../experiments/identity-local/README.md). It does not establish sustainable capacity, enumeration resistance, optimum pools or AWS costs. The browser verification page is not implemented (WEB-02), so emailed local links currently require an API client to complete confirmation. No scoring worker/frontend/Terraform/k6/AWS resources exist. Image compatibility, AWS TLS/recovery/capacity and production pool selection remain unverified; [acceptance ledger](production-acceptance.md) remains NOT ACCEPTED.
