# Phase 03 execution plan

Status: DB-01–11 COMPLETE; DB-12 PARTIAL, 2026-10-06. See [review](phase-03-review.md). Scope DB-01–11 and the DB-12 runbook; old/new application image compatibility remains pending until composition roots/images exist (BOOT-10/CI). No production deployment or capacity result is implied.

1. Add parameterized PostgreSQL infrastructure and a plain application UnitOfWork port. Write failing configuration/connection-budget tests, then implement strict TLS configuration, bounded admission, connection/statement/lock/idle-transaction timeouts, redacted observations and transaction context.
2. Implement join/rollback-only semantics, call-time client resolution and rejection of work using an ended context. Verify commits, rollbacks, caught nested errors, parallel isolation, lock waits and pool exhaustion on PostgreSQL 17, without driver mocks.
3. Write ordered immutable SQL migrations with advisory serialization and SHA-256 checksums. Every migration is atomic; applied files cannot disappear/change or be inserted before the applied prefix. Add separate owner/migration/runtime roles and explicit grants; no runtime DDL, snapshot mutation or audit mutation.
4. Implement capability-owned schemas: Identity credentials/roles/sessions, Catalog drafts and immutable publications, Assessment attempts/answers/results/ranking/statistics, platform receipts/outbox/inbox/audit/rate buckets/import reports. Composite foreign keys bind attempts, questions and selected options to one frozen publication. Database constraints complement application/domain validation; database storage is not an alternate business workflow.
5. Add query-driven index map, connection-budget gate, pg_stat_statements provisioning/diagnostics and expand/contract/rollback runbook. Do not select an optimal pool, add cache/partitioning or claim speedups without realistic data/load.
6. Run fail-first tests, real PostgreSQL integration, build/typecheck/lint/quality/audit, self-review constraints/privileges/context cleanup. Update roadmap, test inventory and evidence with exact results. Keep DB-12 unchecked until application image compatibility is executed.

Ownership: capability tables follow the Phase 02 ownership contract; migrations and pool/UoW are technical platform infrastructure. Presentation/application/domain remain independent of pg/SQL/AsyncLocalStorage. No business repository port is invented before its use case exists. Transaction invariant: all participating adapter calls share one active connection and cannot commit after a joined or SQL error; no queue/network I/O in that transaction.

Local tests create disposable databases under the Compose administrator, provision restricted login roles, apply the real migration files and clean only their own test databases. Main local data volumes are preserved. Runtime config uses a separate DML login. PostgreSQL privilege checks and test fixtures do not replace candidate authorization or real start/save/submit/inbox tests in ATT-10/ASYNC-11.
