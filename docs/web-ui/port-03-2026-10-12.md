## Execution contract and findings

Presentation calls feature controllers and the injected PlatformApi. No direct
transport, new library, backend API, schema, transaction, event or AWS resource.
Catalog remains authoritative for validation, revisions, receipts and atomic
imports. List and detail reads carry answer keys and require catalog.keys.read;
UI bank/preview explicitly omit keys/explanations even for an authorized author.
Creation/edit/archive require catalog.manage; import/report require catalog.import.
Live Admin remains blocked without authoritative capability discovery.

Inspected defects: question form automatically adopts a refreshed revision while
retaining old fields; separate save/archive intent machines allow competing
operations; archive lacks pending state; ambiguous5xx/malformed writes release
their key. Import has split intent machines, mutable file/text while pending and
does not retain a dry-run text snapshot on a lost-ACK retry. Question bank queries
with manage alone despite key-sensitive API requirements. Failing regression
tests preceded the fixes. Protected read/write403 and capability loss hide/purge
private data. A late import response cannot restore it after permission returns.

Question option identity is local and stable across reordering/removal; transport
positions are regenerated and correct positions follow the same options. Type
conversion warns before losing options/keys. Archived form is read-only. Unknown
outcome freezes one exact action/key/body; no new write until resolved.409 keeps
local draft/base revision and requires explicit fresh adoption. No force-save or
automatic merge. Drafts/intents stay in memory; navigation warning is not durability.

Import reads at most1MiB UTF-8/100 entries, no HTML evaluation or answer preview.
Dry-run and commit use distinct keys. Only the exact validated snapshot can be
committed after explicit confirmation. Unknown retry keeps its action/body/key.
Pending file reads cannot overwrite newer input or permission-cleared state.
Reports show actual IDs/timestamps/issues/mappings; no inferred question payload.

## Implementation and review

`use-question-list`, `use-question-editor`, `use-question-draft`,
`use-question-import` and `use-import-report` own reads, permissions and writes.
Views compose existing shared controls; the pure question model owns option
identity/DTO conversion. One small feature navigation helper serves question and
import pages. No pass-through repository/UoW layers are added to the browser.
See [frontend architecture](frontend-architecture.md).

Final self-review also reproduced two races: adopting a cached pre-conflict
revision and archiving before the post-save background read completes. Adoption
now requires a newer revision; archive restores the last acknowledged field
snapshot rather than stale cached fields. Unknown operations retain exact action,
key/body and block competing operations. File reads and requests use invalidation
tickets, so older completions cannot overwrite newer or permission-cleared input.

The bank/form/import use the selected Cobalt–Apricot tokens, self-hosted fonts,
shared white header/rail, cards and controls. Desktop form is2:1; tablet stacks
content and preview. Tables scroll within named regions. Conflict comparison is
840px maximum, stacks below800px, and shows actual fresh/local contents only.
No unsupported action menu, global search, invented totals or fake report fields.

Intentional differences from raster references: current demo seed rows replace
the image's illustrative bank rows; no answer-key column is copied. Candidate
preview is a read-only content projection rather than a second answering engine.
Import retains the original JSON editor below its validation report so edits can
invalidate the exact dry-run snapshot. Native file input follows browser locale.
Real IDs, revisions, timestamps and counts replace hard-coded fixture labels.
