# Persistence comparison protocol — fixed before measurement

2026-10-07. Evaluate pg8.23.1, TypeORM1.1.1 and Sequelize6.37.8 + scoped uuid11.1.1 override. Node24.17/ARM64, Nest12 compiled application, PostgreSQL17 on local Docker. Not an AWS/k6/sustainable-capacity benchmark. Migrations and ports stay unchanged. Candidate PoCs are not installed in API runtime.

Hard local gates: one connection/context, nested rollback-only, no late/detached commits, safe query errors, bounded admission/acquire/statement/lock timeouts, restricted DDL, duplicate profile receipt, audit rollback, stale revision/fingerprint conflict, fail-closed concurrent refresh, crash recovery, and actual HTTP/CSRF/cookie contract. Native dependency diagnostics and compatibility risks remain explicit production-adoption gates even if durable-state tests pass.

Five configurations: pg, typeorm.raw, typeorm.mapped, sequelize.raw, sequelize.mapped. Raw modes use unchanged SQL repositories through the candidate executor. Mapped modes change only account lookup/lock/profile mutation to the owned ORM model; projection/session/security/audit/receipt SQL uses that SAME connection. No automatic migrations/sync, second runtime pool, security stub or faster password hash.

Dataset:100,000 users,100,000 candidate role memberships,100,000 families and100,000 indexed sessions plus at most32 temporary measured identities. Synthetic sessions have valid schema fields but are not usable credentials. This is an Identity dataset, NOT the500,000-question/millions-answer production seed. Four workload populations: account lookup, authenticated principal, signed refresh, audited/idempotent profile. Real ES256 generation/verification; profile saves retain expected revision and fresh UUIDv7 keys. Registration, password login and SMTP are setup/not timed.

Pool4, maxWaiting32, acquire1,000ms, statement2,000ms, lock500ms, idle transaction5,000ms; server timezone/search_path/synchronous_commit and restricted runtime login identical. Connection recycling is not exercised by short runs; Sequelize does not expose pg maxLifetimeSeconds equivalently. Record differences instead of claiming perfectly identical lifecycle controls.

Five blocks, concurrency1/8/32,256 timed operations per workload/configuration/block,32 warmup operations. Rotate candidate order each block. Same indexed database, temporary identities cleaned between configurations. GC before each measured workload. No benchmark runs concurrently with the tests. Closed-loop workers and success/all/failure latency populations; achieved successful RPS includes failures in elapsed time. These short bursts do not establish saturation, sustained capacity or SLO compliance. Small per-run p99 tails remain noisy; retain every sample.

Observe actual driver calls including BEGIN/COMMIT/implicit ORM protocol SQL, connection acquire/pool maxima, lock-query elapsed, transaction elapsed, client process CPU/operation, absolute/delta RSS and heap, GC durations, startup cold process/RSS, PostgreSQL aggregate stats and plans. CPU includes client+application and excludes PostgreSQL Docker CPU. RSS delta is NOT allocated memory/request. Do not record SQL/parameters/credentials in telemetry. Private pinned pool counters are experiment diagnostics only.

Decision: correctness/security/durability failures disqualify adoption. Local comparison tolerances for further-investigation flags (not production SLO waiver): repeatable p95/CPU degradation>10% with absolute latency>1ms, added queries, cold RSS>20%, startup>25%. Report medians and full per-block ranges; do not infer causal benefit from one run. Maintainability/TCO records actual source/dependency/control work and unknown team onboarding/engineering cost, never invented USD or future hours saved. A runtime ORM migration needs demonstrated benefit, staged conversion, full regressions and production capacity/TCO evidence. Keeping pg is an explicit current-scope decision, not a universal performance/cost winner.
